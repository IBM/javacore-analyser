Feature 1

Verbose GC File Support

Verbose GC log files are parsed alongside javacores. Heap usage, GC pause times and collection frequency are rendered as an interactive chart, correlated with javacore timestamps. No external GC analysis tools needed — everything is built in.

Why it matters

  • Spot GC spikes that coincide with thread blocking
  • Detect Stop-the-World pauses causing apparent hangs
  • Correlate heap exhaustion with OOME javacore triggers
  • Too-frequent GC drains CPU and masks root cause
  • Visualise usage of different memory types (heap, nursery, tenured)

GC pause spikes (blue bars) overlaid on heap usage — long pauses flagged automatically in Tips

Feature 2

HAR File Support

HTTP Archive (HAR) files capture network traffic. The tool parses HAR files and displays slow HTTP calls, error codes and payload sizes alongside thread data. No external HAR viewer required — analysis is done directly in the report.

Why it matters

  • Identify slow external calls that cause thread wait states
  • Detect high-latency endpoints behind application hangs
  • Spot HTTP 5xx errors indicating back-end overload

Typical scenario

App appears hung → javacores show threads waiting on I/O → HAR shows 30-second calls to a downstream REST service returning HTTP 503.

All HTTP calls sorted by duration — slow calls and 5xx errors highlighted, with expandable request/response details

Feature 3

AI-Based Thread Classification

A pre-trained model automatically classifies every thread snapshot into meaningful categories.

Why it matters

  • Surface thread types relevant to your issue instantly (DB waiters, GC threads, HTTP workers…)
  • Classification column visible in All Threads table
  • Thread Classification Over Time chart shows workload shifts
  • Permanently blocked threads detected and flagged in Tips

Each thread gets an AI-predicted class (e.g. Java Internal, Wait For Condition) — visible across all snapshots

Feature 3 — continued

Thread Classification Over Time Chart

A dedicated chart tracks the count of each thread class across all javacore snapshots, making workload changes over time immediately visible.

Reading the chart

  • Wait For Condition — threads blocked on locks or semaphores
  • Java Internal — JVM-managed threads (JIT, GC helpers)
  • Liberty Internal — server framework threads
  • Computing — actively executing application code
  • Read From Network — I/O bound threads

Deadlock signal

If "Wait For Condition" count climbs across snapshots while "Computing" drops → suspect thread starvation or deadlock.

Blue dominates = most threads waiting on conditions — immediately actionable insight without reading stack traces

Feature 4

Tips Enhancements

The Intelligent Tips section is the first place to look. It now produces richer recommendations with actionable evidence and expected impact — plus clickable links to the relevant thread or javacore.

What's new

  • Tips include Evidence, Action and Expected Impact
  • Thread names in tips are clickable — jump straight to the drill-down
  • Javacore filenames in tips link to the javacore detail page
  • Long GC pause tip — fires when STW pauses exceed thresholds
  • Permanently blocked thread tip — instant deadlock signal
  • System exit in main thread detection

Tips ranked HIGH / MEDIUM / LOW with Evidence, Action and Expected Impact — thread names are clickable links

Feature 5

Plugin Architecture

A plugin system lets you extend the tool with custom data source processors — without touching core code. Drop a plugin folder into ~/.javacore_analyser/plugins/ and it auto-loads.

Why it matters

  • Process custom diagnostic file types (e.g. Liberty server logs, JMX exports)
  • Inject custom HTML sections into the report
  • No core modifications — zero risk to existing functionality
  • Reference implementation included in docs/example_plugin/

The Liberty System Out example plugin injects a dedicated report section with severity breakdown and top message IDs
