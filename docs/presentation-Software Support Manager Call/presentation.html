Overview

What is WAIT2 Performance Analyser?

Purpose

Analyses and visualises Java performance data

WAIT2 Performance Analyser processes javacore files and related diagnostic data to help identify performance bottlenecks, thread hangs, memory issues and GC problems — without manual stack trace inspection.

What it analyses

Multiple diagnostic data sources in one run

  • Javacore files — thread states, CPU usage, lock contention
  • Verbose GC logs — heap usage, pause times, collection frequency
  • HAR files — HTTP call durations, status codes, slow endpoints

Where to run it

Available directly on Ecurep

Launch from the Ecurep tool list while browsing a customer case — no Citrix, no local setup, no file download required.

WAIT2 Performance Analyser in the Ecurep tool launcher — select and click Launch directly from the case

Feature 1

Verbose GC File Visualisation

What

Built-in verbose GC analysis

Verbose GC logs are parsed alongside javacores — heap usage, GC pause times and collection frequency are visualised without any external GC tool.

How to use

Include GC logs in your input

  • Add verbose GC log files to your zip, folder or file list
  • The tool auto-detects and processes them alongside javacores

Output

GC Activity chart in the report

  • Heap usage, nursery and tenured memory over time
  • GC pause durations overlaid as bars
  • Long Stop-the-World pauses automatically flagged in Tips

CPU Load (top) and GC Activity (bottom) — heap usage, pause times and collection frequency shown together

Heap oscillates between ~2–4 GB (6 GB total). A single exceptionally long pause (~30 s) is visible at 02:26 — a Stop-the-World event that would cause a severe application stall.

Feature 2

HAR File Support

What

HTTP traffic analysis inside the report

HAR (HTTP Archive) files capture browser/application network traffic. The tool parses them and surfaces slow calls, error codes and payload sizes — no external HAR viewer needed.

How to use

Include HAR files in your input

  • Add *.har files to your zip, folder or file list
  • Capture HAR from a browser DevTools session
  • The tool auto-detects and includes them — no extra steps

Output

HTTP calls table in the report

  • All HTTP calls listed in a table — sort column can be changed
  • Expandable request / response details per call
  • Plan to display long HAR requests or errored requests in Tips

All call durations are below 900 ms, however one request fails with HTTP 400 — this error response is a possible cause of the performance issue being investigated.

Core Capability

Javacore Processing

What

Thread-level analysis across multiple snapshots

Javacore files are IBM JVM diagnostic snapshots capturing thread states, stack traces, CPU usage and lock information at a point in time. The tool processes a series of javacores to reveal patterns that a single snapshot cannot show.

What is analysed

Per-thread and cross-snapshot data

  • Thread states — running, waiting, blocked, parked
  • CPU usage — top CPU consumers identified across snapshots
  • Lock contention — deadlocks and blocked threads detected automatically
  • Stack traces — per-thread drill-down with full call stack

Output

Interactive report sections

  • CPU Load chart showing usage over time across all snapshots
  • All Threads table — sortable, filterable, with per-thread drill-down
  • Intelligent Tips flagging high-CPU threads, deadlocks and blocked threads

All Threads table — every thread across all javacore snapshots, sortable by CPU usage, state and classification

Feature 3

AI-Based Thread Classification

What

Automatic thread categorisation by a pre-trained model

Every thread snapshot is classified into a meaningful category (e.g. Computing, Wait For Condition, Read From Database) without any manual inspection.

How to use

Nothing extra — runs automatically

  • Classification runs on every javacore analysis automatically
  • No additional files or configuration required

Output

Classification column + Over Time chart

  • Classification column visible in the All Threads table
  • Thread Classification Over Time chart shows workload shifts
  • Permanently blocked threads flagged in Tips

Each thread gets an AI-predicted class (e.g. Java Internal, Wait For Condition) — visible across all snapshots

Thread Classification Over Time chart

Shows the most used resources (database, disk, CPU) over time to detect bottlenecks.

Feature 4

Tips

What

Two entry types: Warnings and Tips

  • Warning — flags a data quality or reliability issue (e.g. corrupted javacore, too few snapshots); indicates the investigation results may not be reliable
  • Tip — identifies a potential cause of a performance problem (e.g. high CPU thread, deadlock, long GC pause); includes Evidence, Action and Expected Impact

How to use

Open the Intelligent Tips section

  • Tips are generated automatically — no extra input needed
  • Click a thread name in a tip to jump to its drill-down
  • Click a javacore filename to open the javacore detail page

Output

Examples of common tips

  • High CPU thread — thread consuming excessive CPU across multiple snapshots; includes thread name and stack trace
  • Long running request in HAR file — HTTP request exceeding response time threshold; URL and duration shown as evidence
  • Long GC pause — Stop-the-World pause exceeding threshold; heap usage and pause duration shown as evidence

Tips ranked HIGH / MEDIUM / LOW with Evidence, Action and Expected Impact — thread names are clickable links

Feature 5

Tool Integration via Plugin Architecture

What

External tools can contribute report sections

A plugin system allows external diagnostic tools to inject dedicated sections into the report automatically — no manual steps, no separate viewers.

Available now

Liberty message occurrence plugin

  • Detects and parses Liberty server logs included in the input
  • Injects a dedicated section with message severity breakdown and top message IDs
  • No additional configuration required

Planned

  • Include Autogather output in your zip or folder
  • Autogather data will appear as a dedicated section in the report

Developer Tools Debug console output

  • Include Developer Tools debug console export in your input
  • Console messages and errors will appear as a dedicated section in the report

The Liberty System Out example plugin injects a dedicated report section with severity breakdown and top message IDs
